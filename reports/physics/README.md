# Physics-input comparison: current vs. new datasets (Pin Point, GA)

Generated by `src/scripts/physics_input_comparison.py` (coral conda env). Domain crop:
Pin Point bbox `[-81.1557, -81.1181, 31.9278, 31.9601]`, on the same 30 m Savannah DEM
grid (`SUB_DEM_SAV.asc`) the LISFLOOD run uses, so pixels line up 1:1 with the model's
Manning/infiltration inputs.

New source data: `data/raw/sagis_pinpoint/sagis_wetlands_nwi.geojson` (NWI, 62 polygons)
and `sagis_soils_nrcs.geojson` (SSURGO map units, 77 polygons, 17 distinct MUKEYs) via
`coral.preprocess.fetch_sagis --group physics`. SSURGO Ksat/AWC per MUKEY resolved via
USDA Soil Data Access (SDA) REST — `src/coral/preprocess/fetch_ssurgo.py` — written to
`data/raw/ssurgo_pinpoint/ksat_awc_by_mukey.json` (16/17 MUKEYs resolved; MUKEY 1678303,
musym "W"/open water, has no soil horizon record, as expected).

## Manning's n: NLCD (current) vs NWI-refined

- **`manning_n_maps_current_vs_nwi.png`** — side-by-side maps of current NLCD-derived n,
  NWI-refined n, and the difference. **54.7% of land cells** in the Pin Point crop fall
  inside an NWI wetland polygon and get reassigned.
- **`manning_n_histogram_current_vs_nwi.png`** — value distributions. Current median
  n = 0.061 (NLCD's dominant land classes here are open water/low n); NWI-refined median
  n = 0.110 (dominated by Estuarine/Marine emergent marsh, n=0.11).

**Calibration implications**: the NWI overlay pushes Manning's n *up* by roughly 0.05
across roughly half the domain — Pin Point is genuinely marsh-dominated at the 30 m
NLCD resolution undersells, and NLCD's wetland classes (90/95, n=0.086/0.061) already
sit below the NWI-informed values (0.11-0.16) used here. Since higher n slows overland
flow and increases attenuation/ponding, expect the NWI-refined grid to **damp inland
propagation speed of both surge overtopping and pluvial flow**, and to raise simulated
peak stage locally in marsh cells relative to the current run. This is the single
biggest-leverage change of the two datasets, because it directly touches half the
domain's land cells. Recommend calibrating storm-surge HWM residuals against the
NWI-refined grid first, since the current grid likely underestimates roughness in the
marsh fringe that dominates flow near the gauges.

## Ksat: POLARIS (current) vs SSURGO

- **`ksat_maps_current_vs_ssurgo.png`** — current POLARIS-derived Ksat rate grid
  (`infil_matthew_compound.asc`, already produced for a prior run) vs. SSURGO ksat_r
  rasterized from the 17 map units, plus the difference map.
- **`ksat_histogram_current_vs_ssurgo.png`** — distributions. Current (POLARIS) median
  ≈ **57.6 mm/hr** [range 0-651]; SSURGO median ≈ **100.8 mm/hr** [range 2.2-331].

**Calibration implications**: SSURGO pushes the *typical* Ksat roughly **1.7x higher**
than POLARIS but with a narrower, less extreme tail (POLARIS's max of 651 mm/hr looks
like a resampling/edge artifact; SSURGO's component-weighted values are smoother because
they're literal map-unit lookups, not machine-learning-interpolated pixels). A higher
Ksat means more/faster infiltration in the constant-rate (`infil_capped: false`) mode,
which in the current surge-only over-drainage diagnostic (docs/MODEL_INPUTS.md, -0.12 m
coastal bias) would make the over-draining problem *worse*, not better — this reinforces
the case for keeping `infil_capped: true` (AWC-limited) rather than raising Ksat further.
The map shows this is patchy, not uniform — recalibrate per-MUKEY rather than with a
single domain-wide multiplier.

## AWC / storage capacity: POLARIS (current) vs SSURGO

> **Reconciled.** An earlier draft of this section compared POLARIS `infilcap`
> against SSURGO **`awc_r`** and reported a "~10× gap." That was a **variable-definition
> mismatch, not a real disagreement**: `infilcap` is drainable-porosity storage
> (θ_s − θ_r), while `awc_r` is *plant-available* water (field-capacity − wilting-point)
> — a physically different, much smaller quantity. The comparison below now uses the
> matched SSURGO analog `sat_storage_mm = (wsatiated_r − wfifteenbar_r) × 50 cm`.

- **`awc_maps_current_vs_ssurgo.png`** — current POLARIS `infilcap`
  (`infilcap_matthew_compound.asc`, depth-weighted θ_s − θ_r over 0-50 cm) vs. the
  corrected SSURGO `sat_storage_mm`, plus difference map. (`awc_r`×500 mm is retained
  only as a clearly-labeled annotation series.)
- **`awc_histogram_current_vs_ssurgo.png`** — distributions. POLARIS median ≈ **206 mm**
  [37-325]; corrected SSURGO `sat_storage_mm` median ≈ **137 mm** [31-200] on the Pin
  Point grid (≈ **155 mm** by raw MUKEY). The old, non-comparable `awc_r`×500 mm sits at
  ≈ 20 mm — that number should be ignored for infiltration.

**Calibration implications**: once the right SSURGO variable is used, the gap collapses
from ~10× to **~1.3-1.5×** — POLARIS and SSURGO broadly agree that these sandy/hydric
soils (Lakeland sand, Chipley fine sand, tidal marsh) can absorb ~150-200 mm before
saturating. SSURGO runs modestly *lower*, so swapping it in would somewhat *reduce*
soil storage → slightly earlier inland ponding, but nowhere near the dramatic effect the
erroneous 20 mm implied. This is now a **second-order calibration knob**, not a red flag.
Any swap should still be re-validated against HWMs, since the +capped mode's `infilcap`
also governs how much surge-driven wetting is "used up" before the domain saturates
(docs/MODEL_INPUTS.md §4b) — but the earlier alarm about ~10× over-crediting was an
artifact of comparing the wrong two quantities.

## Notes / limitations

- Manning's n comparison uses actual NLCD raster (`nlcd_savannah.tif`, found in the
  sibling `coastalFlood/savannah_matthew_workflow/inputs/` directory) + real NWI
  polygons — a true per-cell map comparison, not just a lookup-table comparison.
- Ksat/AWC comparison uses the **existing POLARIS-derived rasters** from a prior coral
  run (`lisflood_compound_infilcap_run/infil_matthew_compound.asc` and
  `infilcap_matthew_compound.asc`) rather than regenerating them (POLARIS's Duke server
  fetch was not re-run this session; the existing rasters are on the identical DEM grid,
  so they're a valid current-vs-new comparison).
- The headline SSURGO storage term is `sat_storage_mm = (wsatiated_r − wfifteenbar_r)
  × 50 cm` (satiated minus wilting-point water content), the matched analog of POLARIS's
  θ_s − θ_r × 50 cm. SSURGO `awc_r` (plant-available water) is **not** comparable to
  `infilcap` and is shown only as an annotation; using it was the source of the earlier
  spurious ~10× gap.
- 1 of 17 MUKEYs (musym "W", open water/marsh channel) had no SDA horizon record and
  was skipped, leaving small nodata gaps in the SSURGO rasters.
